Kaya uses a simple role model for application access.

| Role | Access |
| --- | --- |
| Viewer | Read-only access to most authenticated pages |
| Editor | Create and update operational records |
| Admin | Manage users, settings, audit logs and administrative workflows |

## First administrator

The first administrator is created from `/setup` when Kaya starts with an empty user table.

After setup, admins can create and edit users from the Team area.

## User management

Administrators can:

- Create users.
- Edit names, email, role and active status.
- Set or change passwords.
- Reset another user's 2FA configuration.

## Authentication features

Kaya supports:

- Email/password login.
- Argon2 password hashing.
- Optional TOTP two-factor authentication.
- Password reset by email when SMTP is configured.
- Session activity tracking.

## Permission model

Permissions are enforced per route with FastAPI dependencies. Kaya currently has coarse-grained roles rather than per-object permissions.
