Kaya is intended to run as a self-hosted Docker Compose application with persistent application data, uploaded files and remote session recordings.

The Kaya repository is:

```text
https://github.com/antybubbs/Kaya.git
```

The published container image is:

```text
ghcr.io/antybubbs/kaya:latest
```

<Callout type="info" title="Recommended install path">
Use the latest release tag for stable installs. Use a branch only when testing unreleased Kaya changes or contributing to development.
</Callout>

## Before you begin

- A Linux host or virtual machine with Docker and Docker Compose installed.
- Git installed on the host.
- A DNS name if you plan to expose Kaya through HTTPS.
- Persistent storage for `data/`, `uploads/` and remote recordings.

## One-command install from the latest image

```bash
git clone https://github.com/antybubbs/Kaya.git kaya
cd kaya
docker compose up -d
```

Open `http://localhost:8080`, then visit `/setup` to create the first Kaya administrator.

## Install from the latest release tag

Use this path for stable source-controlled installs.

```bash
git clone https://github.com/antybubbs/Kaya.git kaya
cd kaya
git fetch --tags
LATEST_TAG=$(git tag --sort=-v:refname | head -n 1)
git checkout "$LATEST_TAG"
KAYA_IMAGE="ghcr.io/antybubbs/kaya:$LATEST_TAG" docker compose up -d
```

At the time this page was last checked, the latest published Kaya tag was `v0.21.4`.

## Install from a branch

Use this path for testing unreleased Kaya work. Branch installs build the checked-out source locally and run that local image.

Install from `main`:

```bash
git clone --branch main --single-branch https://github.com/antybubbs/Kaya.git kaya
cd kaya
docker build -t kaya:main .
KAYA_IMAGE=kaya:main docker compose up -d
```

Install from the current development branch:

```bash
git clone --branch dev0.23.0 --single-branch https://github.com/antybubbs/Kaya.git kaya
cd kaya
docker build -t kaya:dev0.23.0 .
KAYA_IMAGE=kaya:dev0.23.0 docker compose up -d
```

## Runtime configuration

Common Compose variables:

| Variable | Default | Purpose |
| --- | --- | --- |
| `KAYA_IMAGE` | `ghcr.io/antybubbs/kaya:latest` | Container image to run |
| `KAYA_PORT` | `8080` | Host port for Kaya |
| `BASE_URL` | `http://localhost:8080` | Public URL used by Kaya |
| `ALLOWED_HOSTS` | empty | Additional trusted hostnames |
| `SESSION_COOKIE_SECURE` | `false` | Set to `true` behind HTTPS |

Kaya also stores generated runtime secrets in `data/.runtime.env` when they are not provided explicitly.

## Persistent data

The Compose file persists:

```yaml
volumes:
  - ./data:/app/data
  - ./uploads:/app/uploads
  - ./data/remote-recordings:/app/data/remote-recordings
```

Back up `data/`, `uploads/` and `data/remote-recordings/`. The `data/.runtime.env` file is especially important because it contains the encryption key needed to decrypt stored secrets.

## First login

After startup:

1. Open `http://localhost:8080/setup`.
2. Create the first Kaya administrator.
3. Sign in and review Site Administration settings.
