Kaya's notification system provides alerts for important operational events across supported modules.

Notifications can be delivered through:

- **In-app notifications**, shown in Kaya's notification centre;
- **PWA Web Push**, delivered to registered browsers and installed devices;
- **Email**, when email notifications are enabled and configured.

Notifications are generated by Kaya's backend services. The Kaya web interface or mobile PWA does not need to be open for a Push notification to be sent.

<Callout type="info" title="Delivery depends on the event">
Only events registered and connected to the central notification service can generate notifications. The available events depend on the modules enabled within your Kaya installation.
</Callout>

### Open the notification centre

Select the **bell icon** beside your user avatar.

The dropdown shows recent notifications and the current unread count. From here, you can:

- Open a notification;
- Mark notifications as read;
- Open the full notification centre;
- Go directly to your notification preferences.

The full notification centre is also available from:

**User Profile > Notifications**

The notification centre provides filters for:

- Read or unread status;
- Severity;
- Module.

Notifications remain available in Kaya even where Push or email delivery fails.

### Notification severity

Kaya uses the following notification severity levels:

- **Info** for general information;
- **Success** for completed operations and recoveries;
- **Warning** for conditions that require attention;
- **Critical** for outages, failures and security-related events.

Your administrator may set a minimum severity for an event. You can also set a personal minimum severity where user customisation is permitted.

### Configure your preferences

Open:

**User Profile > Notification preferences**

Preferences are configured separately for each registered event.

Depending on the installation policy, you may be able to enable or disable:

- In-app delivery;
- PWA Push delivery;
- Email delivery;
- Minimum severity.

Site Administration policy always takes precedence over personal preferences. An option may be unavailable when:

- The delivery channel is disabled globally;
- The event is disabled globally;
- The event is mandatory;
- Your administrator has disabled user customisation;
- The required service has not been configured.

<Callout type="info" title="Missing preferences inherit the installation default">
Where you have not explicitly changed an event preference, Kaya uses the default configured by the administrator.
</Callout>

### Enable PWA Push on a device

PWA Push registration is specific to each browser and device.

To enable Push:

1. Open Kaya using the device that should receive notifications.
2. Go to **User Profile > Notification preferences**.
3. Select **Enable push notifications on this device**.
4. Accept the browser or operating-system permission request.
5. Enable Push for the events you want to receive.

After registration, the device should appear as an active browser subscription in Kaya.

Push notifications can be delivered while Kaya is closed because the backend sends the notification through the browser's Push service and Kaya's service worker displays it.

### iPhone and iPad

On iPhone and iPad, Kaya must be installed as a Home Screen web app before PWA Push can be enabled.

To install Kaya:

1. Open Kaya in Safari.
2. Select **Share**.
3. Select **Add to Home Screen**.
4. Open Kaya from the new Home Screen icon.
5. Sign in and enable Push from your notification preferences.

Also check:

**iOS Settings > Notifications > Kaya**

Ensure that notifications are allowed and that the required display options are enabled, including:

- Lock Screen;
- Notification Centre;
- Banners;
- Sounds, if required.

Focus modes, Sleep mode and Do Not Disturb can delay or suppress how notifications are displayed by iOS.

### Android and desktop browsers

On supported Android and desktop browsers, Kaya can normally register Push directly from the installed PWA or browser.

The browser must:

- Support the Push API and service workers;
- Allow notification permission;
- Access Kaya over HTTPS;
- Have an active subscription registered with Kaya.

Registration is browser-specific. Registering Chrome does not automatically register Edge, Firefox or another device.
